Lista Duplamente Encadeada

Cada nó aqui guarda dois ponteiros — prev e next — em vez de só um. O custo é memória extra por nó; o ganho é poder andar nos dois sentidos e, principalmente, remover o último nó em O(1): como cada nó já sabe quem vem antes dele, não é preciso percorrer a lista para achar o penúltimo. Repare também que, para acessar uma posição no meio, dá para partir do lado mais perto — da cabeça ou da cauda — o que uma lista simples nunca pode fazer.

Como isso é declarado
typedef struct No {
    int valor;        /* o dado guardado no nó */
    struct No *prev;  /* nó anterior (NULL na cabeça) */
    struct No *next;  /* nó seguinte (NULL na cauda) */
} No;

No *head = NULL;      /* primeiro nó */
No *tail = NULL;      /* último nó — é o que torna remover do fim O(1) */
class No:
    def __init__(self, valor):
        self.valor = valor  # o dado guardado no nó
        self.prev = None    # nó anterior (None na cabeça)
        self.next = None    # nó seguinte (None na cauda)

head = None                 # primeiro nó
tail = None                 # último nó: é o que torna remover do fim O(1)

São dois ponteiros por nó (prev e next) e dois de entrada na lista (head e tail). Toda inserção ou remoção precisa religar os dois lados dos vizinhos — é isso que as setas nos dois sentidos mostram.

Em Python, prev e next são referências comuns e None marca as pontas. A regra continua a mesma: toda inserção ou remoção religa os dois lados dos vizinhos.

O ponteiro prev muda tudo

Três consequências diretas de cada nó também apontar para trás:

1
Remover do fim vira O(1)A lista simples precisa percorrer tudo para achar o penúltimo nó. Aqui, tail.prev já é o penúltimo — zero percorrimento.
2
Remover um nó já encontrado é diretoNuma lista simples, remover o nó X exige ter guardado o nó anterior durante a busca. Aqui, X.prev e X.next já bastam: X.prev.next = X.next e X.next.prev = X.prev.
3
Acesso pelo lado mais pertoPara achar a posição i, dá para comparar i com i a partir do fim e percorrer a partir de quem estiver mais perto — cabeça ou cauda.
Lista simples

Um ponteiro por nó (next). Menos memória, mas só anda para frente: remover do fim é O(n), e remover um nó dado exige rastrear o anterior durante a busca.

Lista dupla

Dois ponteiros por nó (prev e next). Mais memória (um ponteiro extra por nó), mas anda nos dois sentidos: remover do fim é O(1), e remover um nó já encontrado nunca precisa de rastreamento extra.

Ambas as pontas

Inserir/remover: O(1)

Com ponteiros head, tail, prev e next, as duas extremidades custam o mesmo: uma troca de ponteiros, não importa o tamanho da lista.

Posição i / valor

Ainda O(n)

Achar o meio da lista continua exigindo percorrer nó a nó — só que agora dá pra escolher o lado mais curto, o que corta o percorrimento pela metade no pior caso.

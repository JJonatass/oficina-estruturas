Struct na memória

Uma struct guarda seus campos em sequência, na ordem da declaração. Para que cada campo comece num endereço alinhado, o compilador insere bytes vazios de padding. Monte structs, clique nos campos para ver o offsetof de cada um e descubra por que sizeof nem sempre é a soma dos tamanhos.

A struct atual em código

Em C, a ordem dos campos define o layout na memória, e sizeof inclui o padding. O código acima é gerado a partir dos campos que você montar.

Uma @dataclass declara os mesmos campos, mas o Python guarda cada valor como um objeto à parte: não há padding visível nem sizeof fixo. Quando o layout importa (arquivos binários, rede, C), usa-se o módulo struct ou ctypes.

Acessar um campo

Endereço + deslocamento

p->nota vira, na compilação, “o endereço em p mais offsetof(Aluno, nota)”. É uma conta só, O(1), como o v[i] de um vetor.

Vetor de structs

turma[i].campo

O endereço é base + i × sizeof(Aluno) + offsetof(Aluno, campo). Por isso o padding final existe: sem ele, o segundo elemento começaria desalinhado.

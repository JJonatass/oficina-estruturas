Lista Sequencial (Vetor)

A forma mais direta de guardar uma sequência: um vetor comum, de capacidade fixa, onde os elementos ocupam posições contíguas 0, 1, 2, … sem buracos. Acessar qualquer posição por índice é O(1) — mas inserir ou remover no meio exige deslocar fisicamente todo mundo depois dela, uma posição de cada vez. É esse custo de deslocamento que a lista encadeada, mais adiante nesta trilha, existe para evitar.

Como isso é declarado
#define CAPACIDADE 8

typedef struct {
    int dados[CAPACIDADE];  /* o vetor: posições contíguas 0..CAPACIDADE-1 */
    int tamanho;            /* quantas posições estão em uso (a linha tracejada) */
} ListaSequencial;
CAPACIDADE = 8

class ListaSequencial:
    def __init__(self):
        self.dados = [None] * CAPACIDADE  # o vetor: posições 0..CAPACIDADE-1
        self.tamanho = 0                  # quantas posições estão em uso (a linha tracejada)

A lista inteira é uma única struct: o vetor dados (as caixas) e o contador tamanho (a linha tracejada que separa o ocupado do livre). Inserir ou remover no meio mexe em dados[i] um a um e, no fim, atualiza tamanho.

Em Python, a mesma ideia vira uma classe: dados é uma lista criada já com CAPACIDADE posições e tamanho conta quantas estão ocupadas. Usamos tamanho fixo de propósito, para enxergar o deslocamento; a list nativa faz isso escondido (e cresce sozinha).

Lista sequencial (vetor)

Acesso por índice é O(1) — é só aritmética de endereço. Mas inserir ou remover em qualquer posição que não seja o fim exige deslocar todos os elementos depois dela: O(n) no pior caso, e a capacidade é fixa de antemão.

Lista encadeada

Inserir ou remover é O(1) uma vez que se tem o nó certo em mãos — basta religar dois ponteiros, sem mover nada. O custo que ela paga: acessar a posição i exige percorrer i nós a partir do início, também O(n), e cada nó carrega um ponteiro extra.

Custo de cada operação

OperaçãoCustoPor quê
Acessar posição iO(1)Endereço do elemento = início do vetor + i × tamanho_do_elemento — cálculo direto, sem percorrer nada.
Inserir/remover no fimO(1)Nenhum elemento precisa se mover — só escreve (ou limpa) a última posição ocupada.
Inserir/remover no início ou meioO(n)Todo elemento depois da posição afetada desloca uma casa — no pior caso (posição 0), são n movimentos.
Buscar um valorO(n)Sem informação extra sobre a ordem dos dados, é preciso comparar posição por posição até achar (ou chegar ao fim).
Vantagem

Acesso aleatório e memória compacta

Nenhum espaço desperdiçado com ponteiros por elemento, e qualquer posição é alcançada em tempo constante — essencial para algoritmos de ordenação e busca binária, que dependem de acesso rápido por índice.

Onde aparece de verdade

Arrays, buffers, e a base de quase tudo

O array/vector de qualquer linguagem, buffers de imagem e áudio, tabelas de uma planilha — e a estrutura de apoio por trás de heaps, tabelas hash e dos próprios vetores dinâmicos (ArrayList, Vec), que só adicionam a capacidade de crescer realocando um vetor maior quando o atual enche.

Implementação didática de uma lista sequencial (array-based list) com capacidade fixa. Acesso por índice e inserção/remoção no fim custam O(1); inserir ou remover em qualquer outra posição custa O(n) por causa do deslocamento físico dos elementos; busca por valor é O(n).

Heap Visual

Um heap é uma árvore binária que vive dentro de um array simples — sem ponteiros. O índice i tem filhos em 2i+1 e 2i+2, e pai em ⌊(i-1)/2⌋. A única regra é a propriedade de heap: cada pai tem prioridade sobre seus filhos (o menor valor no Min-Heap, o maior no Max-Heap) — não há ordem alguma entre irmãos. Isso torna o topo sempre acessível em O(1), mas a busca por um valor qualquer custa O(n). Abaixo, a mesma estrutura aparece nas duas formas ao mesmo tempo: árvore e array.

Um array é uma árvore completa

Como o heap é sempre uma árvore completa (cada nível cheio antes do próximo começar, preenchido da esquerda para a direita), dá para calcular a posição de pais e filhos só com aritmética de índice — sem guardar nenhum ponteiro:

Filho esquerdo de i2i + 1
Filho direito de i2i + 2
Pai de i⌊(i - 1) / 2⌋
Inserir e remover

O(log n) — sobe ou desce só um caminho

Inserir coloca o valor na próxima vaga livre e o deixa "flutuar" (sift-up) até o pai não ter mais prioridade sobre ele. Extrair o topo troca a raiz pelo último elemento e o deixa "afundar" (sift-down) pelo caminho de maior prioridade entre os filhos. Os dois tocam só um caminho da raiz até uma folha — O(log n).

Buscar um valor

O(n) — um heap não é ordenado

Diferente de uma árvore de busca, os irmãos de um heap não têm ordem entre si — só a relação pai-filho importa. Por isso, procurar um valor qualquer exige examinar o array inteiro. O que é instantâneo (O(1)) é espiar o topo: ele está sempre no índice 0.

Construindo em O(n): heapify

Inserir n valores um a um custa O(n log n) no total. Mas dá para transformar um array qualquer num heap válido em tempo O(n): basta preencher o array na ordem dada e aplicar sift-down a partir do último nó que tem filhos, andando de trás para frente até a raiz — é o que o botão "Novo heap aleatório" faz, e o motivo é a soma geométrica das alturas: a maioria dos nós está perto das folhas e custa quase nada para afundar.

Implementação didática de um heap binário (Min-Heap / Max-Heap) representado por array, seguindo a estrutura descrita por J. W. J. Williams (1964) para o heapsort. Complexidade: O(log n) para inserir e extrair o topo, O(1) para espiar o topo, O(n) para buscar um valor qualquer, O(n) para construir a partir de um array (heapify).

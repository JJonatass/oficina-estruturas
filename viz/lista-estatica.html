Lista Encadeada Estática

A mesma ideia de uma lista encadeada — cada nó aponta para o próximo — mas sem malloc e sem ponteiros de verdade. Os nós vivem dentro de um vetor de capacidade fixa, e o "ponteiro" próximo de cada um é só um índice inteiro nesse mesmo vetor (ou -1 para "nada depois"). As posições ainda não usadas ficam encadeadas entre si numa lista livre, dentro do próprio vetor — alocar um nó é tirar o primeiro da lista livre; liberar um nó é devolvê-lo para lá. É assim que se simula uma lista encadeada em ambientes sem alocação dinâmica.

Como isso é declarado em C 
#define CAPACIDADE 7

typedef struct {
    int valor;   /* o dado guardado no nó */
    int prox;    /* "ponteiro": índice de outro slot, ou -1 = nada */
} No;

typedef struct {
    No  nos[CAPACIDADE];  /* todos os nós vivem aqui, num vetor fixo */
    int head;            /* índice do primeiro nó da lista (-1 se vazia) */
    int livre;           /* índice do primeiro slot livre (-1 se cheio) */
} ListaEstatica;

Cada caixa da animação é um No: valor é o dado e prox é um índice do vetor, não um endereço. head e livre são as duas etiquetas: uma aponta o início da lista, a outra o início da lista de slots disponíveis (as setas tracejadas).

Lista encadeada estática (aqui)

Capacidade fixa, alocada de uma vez só — nunca fragmenta a memória, e a estrutura inteira é um bloco contíguo, fácil de serializar ou mandar inteiro para outro processo. O custo: um índice extra por nó (o "próximo"), e um teto rígido no número de elementos.

Lista encadeada com malloc

Cresce sem limite predefinido, um nó por chamada de malloc. Em troca, paga o custo (e a imprevisibilidade) do alocador a cada inserção/remoção, e os nós ficam espalhados pela memória — nada de bloco único.

Custo de cada operação

OperaçãoCustoPor quê
Inserir/remover no inícioO(1)Só reatribui head e troca um próximo — nenhum percurso necessário.
Inserir/remover no meio ou fimO(n)É preciso percorrer a partir de head até achar o predecessor — não existe acesso direto por posição.
Acessar posição iO(n)Mesmo problema: só dá para chegar na posição i seguindo i ponteiros a partir de head.
Alocar/liberar um nóO(1)Tirar ou devolver o topo da lista livre — sempre a mesma operação simples, não importa a capacidade.
Vantagem

Sem fragmentação, memória previsível

Toda a estrutura cabe num único vetor alocado de uma vez — ótimo para orçamentos de memória fixos, e trivial de salvar em disco ou mandar pela rede como um bloco de bytes, sem precisar "seguir ponteiros" para reconstruir a lista do outro lado.

Onde aparece de verdade

Firmware, pools de objetos, alocadores

Sistemas embarcados sem heap dinâmico, pools de objetos reutilizáveis em motores de jogos (evitar malloc a cada frame), e é literalmente assim que o próprio alocador de memória de uma linguagem organiza seus blocos livres.

Implementação didática de uma lista encadeada estática (cursor-based) com capacidade fixa: nós {dado, próximo} vivem num vetor, "próximo" é um índice (não um ponteiro real), e um free list encadeado dentro do mesmo vetor controla a alocação. Inserir/remover no início é O(1); em qualquer outra posição é O(n) por causa do percurso necessário para achar o predecessor.
